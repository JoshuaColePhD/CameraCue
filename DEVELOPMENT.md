# CameraCue development notes

## Background processing and saved-video edits

- `CameraBackgroundProcessor` combines Vision person segmentation and Core Image compositing. Real-time capture uses balanced masks at up to 15 Hz; file-based exports use accurate masks for every frame. The preview and primary writer consume the same processed frame; the preview alone is mirrored.
- `ProcessedMovieWriter` uses AVAssetWriter for H.264/AAC. `CaptureMoviePair` optionally stores an unmodified camera copy in `.Originals`. Camera recording performs MP4 export only after writer finalization, retaining recoverable MOVs on failure.
- `RecordingBackgroundEditor` renders a representative preview frame and runs an asynchronous, cancellable export. `VideoBackgroundExport` preserves source files, handles rotation, waits for offline encoding backpressure, and reattaches source audio tracks at their offsets.
- Optional `RecordingBackgroundMetadata` sidecars link versions to their original source. Missing/malformed sidecars fall back to the visible video; source paths must remain within the recording folder. Personal recording fixtures and historical reviews are deliberately excluded from the repository.
- `SavedVideoPlayer` wraps native AVPlayerView because the target runtime's SwiftUI VideoPlayer wrapper crashes during metadata initialization. Playback pauses and disconnects on teardown.

## Camera video recording

- Apply connection mirroring through `CameraMirroring`: check support and disable `automaticallyAdjustsVideoMirroring` before assigning `isVideoMirrored`. AVFoundation raises an Objective-C exception if automatic mirroring remains enabled, which Swift `do/catch` cannot recover from. Preview and recording output share this safe ordering; regression fixtures verify it.

- `CameraRecording` owns permissions, device choices, preview, capture/export state, destination, and saved/recovery URLs. `MovieCapturing` allows isolated capture fixtures; `NativeMovieCapture` owns AVFoundation session configuration on a serial queue and video/audio data outputs on a separate frame queue. `CaptureMoviePair` writes processed footage and, optionally, an untouched camera original with shared timestamps and microphone samples. Delegates resolve async start/finish continuations, with bounded waits and unexpected-stop feedback.
- `TeleprompterModel.start()` prepares camera access when enabled, prepares speech, completes count-in, then starts the movie before running the take clocks. Generation checks stop late starts after cancellation. Pause keeps camera recording; Finish/Reset stop and save it. The model forwards recorder changes for faithful notch/Studio updates. Saving prevents a new camera take. Defaults are disabled for `defaults: nil` fixtures and enabled for the real app unless explicitly turned off.
- `CameraRecordingView` exposes camera and recording-microphone selection, an explicit preview, save-folder choice, and result/recovery actions. Voice Follow's AVAudioEngine uses system default input independently. Preview mirroring does not mirror saved footage. No camera capture begins on app launch or device enumeration.
- Camera output writes a unique MOV into the selected folder, then exports MP4. Compatible footage uses passthrough; other footage uses high-quality conversion. Original footage is removed only after successful export. Failed conversion retains MOV and allows retry, removing only this attempt's partial MP4. Quit handling waits for save and keeps the app open if recovery is needed.
- `CameraRecordingTests` cover lifecycle failures, cancellation, continuous video across prompting pauses, Stop routing, and retry with isolated data. `VideoExportTests` uses generated pixels and WAV audio through real AVFoundation export; it requires access to macOS encoding services but no camera/microphone. Hardware acceptance limits are documented in `QUALITY_REVIEW.md`.

## Coordinated notch motion

- `NotchMotion` is the internal timing source (300 ms open, 240 ms close, shared smooth curve). `NotchSurface` animates shell/mask paths and control positions directly in Core Animation. It reads presentation layers before replacing animations and guards completion with a transition generation. No animation frames are published through SwiftUI.
- Logo hit rectangles may change width, but `NotchControlCell` draws a fixed-size source image. Hit testing and moving-control click handling use visible layer positions. Timer/Record interaction and accessibility follow the explicit transition lifecycle; ongoing compact Stop remains available.
- Timer popovers reserve stable card heights across modes. `TimerPopoverPlacement` chooses an inward edge near display boundaries. The native popover retains transient dismissal and Done/Return/Escape actions.
- `NotchMotionTests` and `TimerPopoverTests` need WindowServer access for mounted presentation-layer and edge-placement acceptance. Set `CAMERACUE_PROFILE_MOTION=1` to collect repeated-transition display-link timing; `CAMERACUE_TIMER_SNAPSHOTS=1` writes an isolated timer snapshot in `/tmp`. Hardware measurements and their limits are recorded in `QUALITY_REVIEW.md`.

## Studio dashboard

- `ScriptDashboardQuery` supplies title/content search, intersecting All/Has text/Drafts/Favorites filters, deterministic sorting, and the featured choice. A selected spoken script takes priority; otherwise the most recently edited spoken script appears above newer empty drafts. Home shows the featured opening preview and creation cards; All scripts/Favorites use the full workspace. The sidebar lists at most four recent scripts.
- `ScriptLibrary.dashboardEntries()` memoizes text summaries by script ID and exact source body. Title/style changes use current record values; body changes refresh counts, excerpts, and estimates. Cache entries for deleted scripts are discarded. These values are derived in memory and do not change the saved JSON schema or source wording.
- Excerpts omit bracketed delivery cues and retain the original spoken text. `excerptLines` preserves the first three spoken lines separately for Home. Estimated reading time uses normalized spoken tokens at 135 words per minute, rounded up to seconds. Sidebar, dashboard, and editor share the estimate. Has text means spoken words exist; microphone readiness remains in Present.
- `ScriptRecord.favorite` is optional for compatibility with existing JSON; missing values mean false. ID-based rename/favorite/delete APIs leave selection unchanged unless the selected script is deleted. Duplicate selects a new record and preserves source/style. Row dialogs capture the target ID rather than implicitly acting on the selected script. Delete confirmation is required and the final script is retained.
- The dashed import card and Studio share one provider handler. File URL/plain-text imports retain size/format checks and automatic word-preserving formatting. Progress, successful completion, local fallback, and changed-source attention messages are visible in the editor and Home. This pass does not change the AI generation service.
- `StudioView.openScript(_:at:)` carries the requested Write/Rehearse destination through the selected-ID observer. Direct rehearsal never starts capture. Rehearse shortcuts are disabled while the display is locked by a take; editing continues to follow the existing queued-change behavior.
- Sidebar rows use explicit Button actions instead of relying on implicit List selection. The entire row content is a hit target, with selected-state accessibility values and visible keyboard focus. This fixes the failed sidebar navigation observed during live acceptance checks.
- Studio uses compact action cards, a light sidebar, a consistent card footer height, native search/menus, descriptive accessibility labels, keyboard focus, and Reduce Motion support. Import/drop formatting and reviewable AI drafting keep their existing workflows.
- `DashboardTests` cover body/title search, diacritics, trimmed queries, complete libraries, filter intersections, stable sorting, continuation priority, Unicode excerpts, cue-only drafts, duration estimates, cache refresh, saved-library reopen, and source preservation.

## Presentation and speech

- `TeleprompterModel` owns the active take, frozen script, alignment, smoothed reading position, and explicit presentation phase. It accepts a capture abstraction and clock provider for deterministic tests.
- `PresentationSnapshot` supplies playback state, immediate line target, last reliable word index, timer, delivery cue, recovery, and pace warning. Studio's `LiveNotchPreview` uses the same `NotchSurface` and `NotchReader` as the actual overlay. Preview controls reject pointer and accessibility activation without dimming their appearance.
- Two `PresentationClock` values separate total active presentation duration from the timer segment. Pause excludes idle time from both; Reset timer affects only the segment. `finish()` stops capture, freezes clocks, stores the summary, and releases display locking. The last spoken line does not auto-finish. `latestSummary` survives New take in memory.
- `TrackingFeedback` uses distinct normalized transcripts. Two seconds of unmatched results enter recovery; empty/duplicate results do not. Reliable alignment restores Following. Recovery overrides pace feedback and holds the last reliable position.
- `followedWordIndex` is optional until a medium/high-confidence match. It freezes on silence, low-confidence results, pause, and capture interruption; seeking, changing follow mode, loading a script, and New take clear it. `PerformanceText` splits existing style runs at the matched word’s UTF-16 boundaries, using the same normalized token map as selection formatting. Current word is lavender, completed text dims to 48%, upcoming text preserves delivery styles. Contractions highlight as a single printed word; no font metrics change. Live notch, Studio’s shared preview, and detached reader use this state.
- Alignment drives token position, never a timer. The notch consumes `displayedReadingLineID` immediately with each reliable match. The former 180–560ms model throttle and delayed task are removed. `ReadingScrollMotion` supplies a non-bouncing interpolating spring (234ms perceptual duration at default responsiveness) to both readers, allowing in-flight retargeting. Equatable reading rows receive progress normalized to their own token range, so unaffected phrases skip text rebuilding. Reduce Motion removes scroll animation.
- `PaceFeedback` confirms drift for three seconds, applies hysteresis, and spaces reminders by 12 seconds. A shared pulse ID lets the real panel and preview display the same warning. Native pacing pulses affect only the stationary banner; the timer has no outline or pulse animation. Reset timer rebases progress to remaining words. Manual mode suppresses pace hints.
- `ScriptAligner` reuses a transcript’s word-similarity matrix across overlapping candidate windows. Alignment scoring, confidence gates, and jump limits are unchanged. Speech/token mapping regexes are compiled once. The release benchmark in `scripts/benchmark-speech.swift` replays each growing transcript prefix of a script and reports matching latency/positions; it is not a frame-rate or recognizer-latency measurement.
- `SpeechFollower` captures through AVAudioEngine and Apple Speech. Startup generation checks reject stale permission/capture completions. Duplicate starts are rejected, pauses stop capture, and interruptions preserve position and pause timing. Recognition uses English (US), preferring on-device recognition when supported.
- `AudioInputCheck` measures RMS on the system default input, publishes at 10Hz, and stops when leaving Present, starting a take, or switching workflow. It does not save/transcribe audio.

## Display selection and native shell

- The left CameraCue wordmark and right down/up chevron are native reader toggles with transparent backgrounds, hover/press tint feedback, tooltips, and focus rings. Both dispatch the same reader action; neither starts capture. `CueSymbol.expand` is a downward path; `chevron.down` no longer maps to the right arrow. Static and live previews share the wordmark and right chevron layout.
- `NotchDisplaySelection` chooses a display independently from layout. Studio supplies its actual NSWindow. Idle clicks select a screen using the event’s captured location (converted from its window when needed), rather than the pointer’s later position; mouse movement does not. Startup/count-in and paused takes keep a lock. Disconnect reconciles to an available screen and pauses for explicit Resume.
- `NotchDisplay` holds screen bounds, visible bounds, actual camera housing, safe top, and backing scale. Panel top is `bounds.maxY`, never `visibleFrame.maxY`. The collapsed height fits the reserved top band. External screens use housing=0 and compact widths 220/340 (idle/ongoing take). `NotchLayout.compactBounds` fits notched shoulders to the control union with 12-point outer padding: housing+144 at idle and housing+204 during a take. Both reader toggles clear the measured camera by 8 points. Compact playback adds 60 points on notched displays or 120 externally without changing compact control positions. On external expansion, layout's expanded frame helpers place branding at x32, chevron x110, Record x150, and listening indicator x210; timer remains at the trailing edge. Native view-frame animations share shell timing and honor Reduce Motion. Physical-notch frames retain clearance. `compactFrame` translates asymmetric bounds into screen coordinates. No reserved band suppresses compact visibility; explicit expansion remains available.
- The visible compact surface routes unoccupied space to a reader toggle. Expanded header space does the same, with timer and playback controls routed first to their own actions. Reader body and resize strip keep their existing handlers. Preview remains noninteractive and static previews use the shared expanded frame helpers.
- Housing measurements use auxiliary shoulder widths, independent of screen origin, and round outward to backing pixels. A positive safe-top inset with missing auxiliary areas uses a conservative height-scaled housing fallback; unobstructed displays keep zero housing. The bundle opts out of display safe-area compatibility mode because the overlay explicitly handles the camera obstruction.
- `NotchController` responds to display notifications, Space changes, and sleep/wake. Its one-second header refresh also rechecks menu-band changes. It publishes geometry only when it changes, but also corrects any panel relocation performed by AppKit while displays reconnect. Permission dialogs order the panel out; sleep pauses prompting.
- `NotchSurface` keeps a fixed reader host and animates the CAShapeLayer shell/shared mask with matching cubic path topology: 380ms open, 280ms close, reversible from the presentation-layer path. No per-frame publishing or SwiftUI geometry animation. The default 548×248 reader can grow for wider physical housings and is constrained to the display.
- `NotchResizeHandle` tracks screen-coordinate deltas from mouse-down; moving the window origin cannot amplify them. The broad 16-point bottom strip has a lavender grip, vertical cursor, double-click reset, and accessible height adjustment. It is absent from compact hits/accessibility and disabled in preview. A drag retains mouse ownership through release even beyond the height limit, and collapse, display changes, sleep, or permission prompts cancel tracking cleanly.
- Live height changes resize the existing host and native paths directly with implicit animation disabled. `NotchController` publishes/persists `notchReaderHeight` only on release; the take and reading anchor are unaffected. Height is 248–680 points, additionally capped at 75% of display height and above the Dock. A smaller display clamps geometry without overwriting the saved preference. The reading viewport supplies its own trailing space so the last phrase can still reach the top in a tall reader. Live preview follows the saved size; style review scrolls within the display to keep its footer reachable.
- Wordmark, chevron, and playback controls have fixed hit areas. Ready/finished **Record** is visible only when the reader is expanded; the idle compact state exposes the wordmark and chevron. Ongoing takes retain Stop, Cancel, or Resume after collapse. Hidden Record is excluded from hit routing, accessibility children, accessibility activation, and the native action dispatcher. `NotchRecordControl` uses the logo's coral color for the Record text and its 14-point active Stop square with 2-point corner rounding. A 2.6-second native layer opacity cycle (55–100%) supplies the pulse without model/frame updates or restarts on speech callbacks. Reduce Motion keeps it steady. Startup/count-in shows lavender Cancel; paused shows lavender Resume. The native hit area and focus ring are retained. The real shell and Studio live preview share this control; the static expanded style preview shows the same coral Record label.
- The timer uses a 68-point hit area pinned 32 points inside the expanded shell's right edge, with right-aligned monospaced digits and no icon/background. It remains hidden when compact, retains native keyboard focus and timer-settings activation, and turns coral for overtime without pulsing. The microphone indicator sits between the right chevron and timer, clear of both. Shared geometry preserves those positions during vertical resize, and all previews use the same timer placement.
- `performNotchRecordAction()` starts/resumes, cancels pending startup, or calls `finish()` for an active take. Pressing Record after completion resets and starts a new take. Studio's Practice again remains a reset without capture; the existing keyboard shortcut and Studio retain Pause/Resume. No action controls QuickTime or saves a media recording. Hidden controls are excluded from compact hits/accessibility; previews reject pointer and accessibility activation.
- The panel cannot become key. Hit testing converts AppKit's parent coordinates to flipped local coordinates before checking the visible shell; expanded child routing passes the original parent-space point to super. Transparent areas pass through. First-mouse acceptance is enabled. Automated point conversion is tested, but window-server pointer dispatch still needs a physical check.
- Studio's named window scene allows the notch's Return to script to reopen a closed editor.

## Editing, storage, and AI

- `ScriptLibrary` persists JSON under Application Support/CameraCue. Read failures preserve a recovery copy or block overwriting if backup fails. Imports accept UTF-8 text/Markdown up to 2MB.
- `NativeScriptEditor` is NSTextView with native selection, accessibility, and UndoManager. `ScriptTokenMap` maps UTF-16 selection ranges to normalized spoken token indices, including contractions and Unicode. Bracketed delivery instructions are excluded.
- `PerformanceMoment` adds optional token anchors and delivery cues. Missing fields decode older plans. Rendering intersects global anchors with each reading line, so repeated occurrences and cross-line selections stay precise. Pause adds a reading break without changing source wording; delivery cues are metadata. Formatting undo/redo restores entire plan values while validating the original source.
- Every style application validates spoken-token identity. Source edits invalidate stale style plans. Formatting during a take stays queued for New take. Import AI completions do not overwrite a manual style made while the model was working.
- `PerformanceStyleService` tries Apple's on-device Foundation Models, validates exact phrases, and falls back to local formatting with a visible status. AI review remains separate from automatic import formatting. `ScriptDevelopmentService` previews drafts/revisions and saves accepted output as a new script; errors never silently replace the source.
